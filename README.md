# my-service-agent

고객의 재고 문의에 답하는 서비스 에이전트의 설계 기록입니다. 모델이 창고와 상품을 추측하지 않고, 정해진 도구 계약 안에서만 재고를 조회하도록 설계합니다.

## 구성

| 경로 | 내용 | 상태 |
|---|---|---|
| `design-packet.md` | 설계 패킷(일곱 항목) | 작성 예정 |
| `my-agent/tool-definition.md` | 실습 1 산출물: 읽기 전용 재고 조회 도구 `get_inventory` 정의서와 실행 전 채점 기준 | 완료 |
| `my-agent/traces/` | 실습 2 산출물: 실행 기록 원문 (`trace-01.txt`, `trace-02.txt`, …) | 진행 예정 |

## 설계 결정 요약

- **도구 하나는 동작 하나:** 재고 조회(`get_inventory`)는 읽기 전용으로 두고, 수량 변경은 같은 도구에 넣지 않습니다.
- **창고는 나열형으로 고정:** `warehouse_id`는 `SEOUL-01`, `BUSAN-02`만 허용해 모델이 창고 코드를 지어낼 수 없게 합니다.
- **반환은 답의 근거만:** `sku`, `warehouse_id`, `available_quantity`, `checked_at` 네 필드만 돌려주고, 원가 같은 내부 데이터는 컨텍스트에 넣지 않습니다.
- **실패마다 뒤 행동을 정함:** 허용되지 않은 창고·없는 SKU는 질문, 시간 초과는 한 번 재시도 후 중단합니다. 어떤 경우에도 수량을 추정하지 않습니다.
- **문장과 스키마의 두 겹 방어:** 도구 설명은 모델이 읽는 지시라서 선택을 좁히지만 어길 수 있습니다. 그래서 스키마 검증으로 형식을 강제하고, 스키마로 잡히지 않는 값(SKU 존재 여부)은 실패 뒤 행동이 받습니다.

## 실행하지 않은 것과 이유

- **실습 2 실행 기록(`traces/`):** 아직 진행하지 않았습니다. 진행 후 실행 기록 원문을 추가합니다.
- **설계 패킷(`design-packet.md`):** 아직 작성하지 않았습니다.
