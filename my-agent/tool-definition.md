# 도구 정의서: `get_inventory`

읽기 전용 재고 조회 도구의 계약입니다. 고객이 "부산 창고의 A-17 재고"를 물었을 때 모델이 창고와 상품을 추측하지 않도록, 여섯 항목을 먼저 고정합니다.

## 정의서

| 도구 정의서 항목 | 기록할 내용 |
|---|---|
| 이름 | `get_inventory` (동사 get + 대상 inventory) |
| 하는 일 한 문장 | 승인된 창고의 특정 SKU 가용 수량을 읽기 전용으로 조회합니다 |
| 언제 쓰고 안 쓰는지 | **쓰는 때:** 사용자가 특정 SKU의 특정 창고 재고 수량을 물을 때 씁니다. "부산 창고"처럼 허용 창고 하나로 분명히 대응될 때만 해당 코드(BUSAN-02)로 바꿔 씁니다.<br>**안 쓰는 때:** 수량 변경·입출고 요청, 창고나 SKU가 정해지지 않은 질문(먼저 묻습니다), 가격·원가·배송일 질문에는 쓰지 않습니다 |
| 인자 스키마 | `sku`: 필수, 문자열 3~32자<br>`warehouse_id`: 필수, 나열형 `SEOUL-01` 또는 `BUSAN-02`만 허용<br>그 밖의 인자는 받지 않습니다 |
| 반환 형식 | `sku`, `warehouse_id`, `available_quantity`(0 이상 정수), `checked_at`(확인 시각) 네 필드만 돌려줍니다. 원가 등 내부 데이터는 포함하지 않습니다 |
| 실패 정의와 뒤 행동 | `WAREHOUSE_NOT_ALLOWED` 허용 목록 밖 창고 → 재호출하지 않고 SEOUL-01·BUSAN-02 중 어디인지 **질문**<br>`SKU_NOT_FOUND` 없는 SKU → 비슷한 상품을 추측하지 않고 정확한 SKU를 **질문**<br>`TIMEOUT` 응답 지연·서버 오류 → 한 번 **재시도**, 다시 실패하면 **중단**하고 조회 불가를 안내(수량 추정 금지) |

- 오류 코드 이름은 "실패에 이름을 붙인다"는 원칙에 따라 정했습니다. `WAREHOUSE_NOT_ALLOWED`는 실습 2 구현(`inventory_tool.py`)이 실제로 돌려주는 이름에 맞췄고, `SKU_NOT_FOUND`·`TIMEOUT`은 정의서에만 있고 가정 구현에는 아직 없습니다.
- 이 정의서에서 "부산 창고의 A-17 재고" 질문에 가능한 호출은 `get_inventory(sku="A-17", warehouse_id="BUSAN-02")` 하나뿐입니다. 창고는 나열형이라 지어낼 수 없고, SKU가 없으면 묻게 됩니다.

## 설계 원칙

- **도구 하나는 동작 하나:** 재고 조회와 수량 변경을 한 정의서에 넣지 않습니다. 변경은 별도 도구(예: `update_stock`)의 영역입니다.
- **자유 문자열 최소화:** 창고처럼 값의 목록이 닫혀 있으면 나열형으로, 길이 제한이 있으면 범위로 적어 모델이 지어낼 자리를 줄입니다.
- **반환은 답의 근거만:** 원본 재고 데이터를 통째로 돌려주지 않고 `available_quantity`, `checked_at`처럼 답의 근거가 되는 필드로 제한합니다.
- **실패는 지금 설계:** 실패마다 뒤 행동(재시도·질문·중단)을 정해 두지 않으면 모델은 같은 호출을 되풀이합니다.

## 실행 전 채점 기준

| 채점 기준 | 통과의 이진 정의 | 확인 위치 |
|---|---|---|
| 스키마 준수 | 호출이 3~32자 `sku`와 `SEOUL-01`·`BUSAN-02` 중 하나의 `warehouse_id`만 사용했습니다 | 도구 호출 인자 |
| 호출 성공 | 유효 입력에서 4개 필드 성공 반환 또는 `WAREHOUSE_NOT_ALLOWED`·`SKU_NOT_FOUND`·`TIMEOUT` 중 하나가 남았습니다 | 도구 응답 |
| 결과 사용 가능성 | 최종 답이 `available_quantity`와 `checked_at`만 근거로 삼았습니다 | 최종 답변 |
| 실패 처리 | 오류 뒤 수량을 추정하지 않고 질문·재시도·중단 중 정해진 행동을 택했습니다 | 호출·최종 답변 |
