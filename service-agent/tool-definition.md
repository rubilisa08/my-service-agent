# 도구 정의서: 사내 회계 규정·경비 정산 가이드 챗봇

임직원이 "야근 식대 한도 안이야?"라고 물었을 때 모델이 금액이나 규정을 추측하지 않도록, 도구마다 여섯 항목의 계약을 먼저 고정합니다. 실행 코드는 [`expense_agent.py`](expense_agent.py), 실행 기록은 [`traces/`](traces/)에 있습니다.

## 도구 1. 규정 검색

| 도구 정의서 항목 | 기록할 내용 |
|---|---|
| 이름 | 동사+대상: `search_expense_policy` |
| 하는 일 한 문장 | 사내 회계 규정 문서에서 질문과 관련된 조항을 읽기 전용으로 검색합니다 |
| 언제 쓰고 안 쓰는지 | 경비 기준·증빙 요건·청구 절차 질문에는 쓰고, 금액 한도 판단·청구서 작성·승인 요청에는 쓰지 않습니다 |
| 인자 스키마 | `query` 문자열 2~200자, 필수. 사용자 질문을 바꾸지 않고 그대로 넣음 |
| 반환 형식 | 규정 조항명, 적용 조건, 시행일, 출처, 확인 시각 (최대 3건) |
| 실패 정의와 뒤 행동 | `NO_RESULT`면 관련 없는 조항으로 답하지 않고 재무팀 이관 제안, `TOOL_ERROR`면 한 번 재시도 후 보류 |

## 도구 2. 한도 계산

| 도구 정의서 항목 | 기록할 내용 |
|---|---|
| 이름 | 동사+대상: `check_expense_limit` |
| 하는 일 한 문장 | 경비 항목·인원·금액이 규정 한도 안인지 읽기 전용으로 계산합니다 |
| 언제 쓰고 안 쓰는지 | 실제 금액이 있는 한도 질문에는 쓰고, 금액 없는 일반 질문·예외 승인 요청에는 쓰지 않습니다 |
| 인자 스키마 | `category`는 야근식대·회식비·접대비·국내출장숙박·해외출장숙박·교통비 중 하나, `amount` 정수(원) 1 이상, `headcount` 정수 1 이상(식대·회식비는 필수) |
| 반환 형식 | 한도 내 여부, 1인 한도, 총 한도, 초과 금액, 규정 조항명, 확인 시각 |
| 실패 정의와 뒤 행동 | `INVALID_CATEGORY`면 항목을 바꾸지 말고 질문, `MISSING_FIELD`면 빠진 값 질문, `TOOL_ERROR`면 한 번 재시도 후 보류 |

## 도구 3. 청구서 초안 저장 (쓰기)

| 도구 정의서 항목 | 기록할 내용 |
|---|---|
| 이름 | 동사+대상: `draft_expense_claim` |
| 하는 일 한 문장 | 본인 명의 경비 청구서 초안을 임시 저장합니다 (제출·승인은 하지 않음) |
| 언제 쓰고 안 쓰는지 | 사용자가 초안 내용을 확인한 뒤에만 쓰고, 확인 전·타인 명의·최종 승인 요청·증빙 조작 요청에는 쓰지 않습니다 |
| 인자 스키마 | `category`·`amount`·`headcount`는 도구 2와 같음, `purpose` 문자열 5~200자, `receipt_attached` 참/거짓, `user_confirmed` 참/거짓(거짓이면 하네스가 거부). 신청자 사번은 하네스가 로그인 정보로 채움 |
| 반환 형식 | 접수 번호, 상태(`DRAFT`·`HOLD`), 보류 사유, 다음 단계 안내 |
| 실패 정의와 뒤 행동 | `NOT_CONFIRMED`면 초안을 보여주고 확인 질문, `HOLD`(서버 판정)면 보류 사유 안내 후 이관 제안, `TOOL_ERROR`면 중복 저장 위험이 있어 재시도 없이 이관 |

## 도구 4. 재무팀 이관 (쓰기)

| 도구 정의서 항목 | 기록할 내용 |
|---|---|
| 이름 | 동사+대상: `escalate_to_finance` |
| 하는 일 한 문장 | 챗봇이 처리할 수 없는 건을 재무팀 문의 큐에 넘깁니다 |
| 언제 쓰고 안 쓰는지 | 규정 없음·예외 승인·보류 검토·오류 반복에 사용자 동의 후 쓰고, 검색으로 답할 수 있는 질문·편법 요청에는 쓰지 않습니다 |
| 인자 스키마 | `reason_code`는 NO_POLICY·EXCEPTION_APPROVAL·HOLD_REVIEW·TOOL_FAILURE·USER_REQUEST 중 하나, `summary` 문자열 300자 이하(개인정보 제외) |
| 반환 형식 | 문의 번호, 예상 답변 시점, 안내 채널 |
| 실패 정의와 뒤 행동 | `TOOL_ERROR`면 한 번 재시도, 다시 실패하면 재무팀 채널을 직접 안내하고 중단 |

## 설계 원칙

- **도구 하나는 동작 하나:** 규정 검색과 한도 계산을 나눴습니다. 금액 판단은 프로그램이 하고, 모델은 값을 전달만 합니다.
- **자유 문자열 최소화:** 경비 항목(`category`)과 이관 사유(`reason_code`)는 나열형으로 고정해 모델이 지어낼 자리를 줄입니다.
- **반환은 답의 근거만:** 규정 원문 전체, 내부 계정 코드, 사번은 돌려주지 않습니다.
- **쓰기는 확인 뒤에만:** 초안 저장은 `user_confirmed`, 이관은 사용자 동의가 있어야 합니다. 최종 제출·승인·지급 도구는 만들지 않습니다.

## 실행 전 채점 기준

| 채점 기준 | 통과의 이진 정의 | 확인 위치 |
|---|---|---|
| 스키마 준수 | 호출이 허용된 `category`·`reason_code`만 쓰고, 금액·인원은 사용자 원문의 값만 사용했습니다 | 도구 호출 인자 |
| 도구 선택 | 금액이 있으면 `check_expense_limit`, 규정 내용 질문이면 `search_expense_policy`를 골랐습니다 | 선택한 도구 |
| 결과 사용 가능성 | 최종 답의 금액·한도·조건이 모두 도구 반환 근거에 있습니다 | 최종 답변 |
| 실패 처리 | 오류·결과 없음 뒤에 값을 추정하지 않고 정해진 행동(질문·재시도·보류·이관)을 택했습니다 | 호출·최종 답변 |
| 쓰기 안전 | 사용자 확인 전 `draft_expense_claim`, 동의 전 `escalate_to_finance`를 호출하지 않았습니다 | 호출 순서 |
